## 三、🔴 B1 失败的根因（**我的编排器 bug，已修**）

**现象**：B1 六臂 **rc=2 全灭**（首轮）→ 修参数后重跑 2 个跑完、4 个未跑完即遇停批令。

**首轮根因**：编排器给 B1 写了 `--extra=--smell-channels food`，
但 🔴 **`s2_depletion_probe` 不认 `--extra`**（那是 `_run_s2g2.py` 的参数）
⇒ argparse `unrecognized arguments` ⇒ rc=2。

| 项 | 内容 |
|---|---|
| **修复** | `b1)` 改为 `--arms on --smell-channels food --use-in-move`（探针**直接收**这两个参数） |
| **防复发** | 🆕 新增 **`selftest` 子命令**：起跑前对三组各跑 1 tick 解析校验，**任一组被拒即中止** |
| **验证** | `[OK] a0 / [OK] a1 / [OK] b1` 三组全过（云机实测） |
| **附带修** | 装置守卫的读法也错了（CSV 数据行是**纯数值**，无 `key=` 形式）⇒ 改为读倒数第 3 列 |

**🔴 教训（已写进编排器注释）**：
> **参数透传层必须做"探针是否接受"的校验** —— 否则一个参数名写错就白跑整批。
> 本次代价 ≈ **1.5 h 机时 + 3 h 墙钟**。
